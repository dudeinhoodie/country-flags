# Готовность к релизу

Что проверяется машиной, что руками и что нужно решить человеку до отправки
сборки в App Store. Документ живёт вместе с кодом: если проверка переехала в
CI, строка отсюда уходит.

## Что проверяет CI

| Проверка | Где | Что ловит |
| --- | --- | --- |
| Пакетные тесты | PR | Логика домена, инфраструктуры и стора |
| Гостевой smoke (`LaunchSmoke`, `StudySession`, `SyncStatus`) | PR | Запуск, каталог, тренировка от начала до конца |
| Сборка Dev и Mock | PR | Компиляция обеих отладочных конфигураций и обеих целей приложения |
| Архив Prod без подписи | PR и ночью | Релизная конфигурация вообще собирается и архивируется |
| `check-release-app.sh` | PR, ночью, при релизе | Отладочные аргументы, адрес бэкенда, privacy-манифест, экспортное соответствие, отсутствие mock-бэкенда: бандла, фикстур и строк |
| `check-advertising-policy.sh` | PR | Рекламные SDK, IDFA, ATT |
| `check-signing-entitlements.sh` | PR | Проект потерял `Config/CountryFlags.entitlements` или файл перестал объявлять Sign in with Apple |
| Полный UI-набор | Ночью | Всё остальное: викторина, аккаунт, миграция гостя, офлайн-синк, удаление |
| `AccessibilityUITests` | Ночью | Крупный шрифт, выключенная анимация, русский язык, светлая тема системы |
| Контрактные проверки (`sync-openapi`, флаги, моки) | PR и при релизе | Расхождение с контрактом и с релизом контента |
| gitleaks | PR | Секреты в диффе |

## Что проверяется руками на устройстве

Раз перед отправкой в TestFlight и после смены чего-либо в аутентификации,
уведомлениях или сети.

- [ ] Вход через Apple: согласие, отмена на полпути, повторный вход. Только на
      Prod-архиве: энтайтлмент лежит в проекте, но capability включается у App ID
      в портале Apple, и Dev-сборка этого не докажет.
- [ ] Вход через Google: то же самое, включая возврат в приложение по схеме.
- [ ] Гостевой прогресс переносится в аккаунт после входа.
- [ ] Кейчейн: после переустановки сборки сессия жива, прогресс на месте.
- [ ] Уведомления: запрос разрешения, отказ, повторное включение в настройках системы.
- [ ] Фон и возврат: тренировка на середине переживает сворачивание и звонок.
- [ ] Плохая сеть: режим самолёта посреди тренировки, ответы уходят при возврате связи.
- [ ] Разлогин при обрыве связи не происходит (см. `SessionCoordinator`).
- [ ] Удаление аккаунта: подтверждение, повторный вход, уведомление после перезапуска.
- [ ] VoiceOver: главная, тренировка, оценка карточки, настройки.
- [ ] Крупный шрифт на маленьком экране (SE): ничего не обрезано.
- [ ] О приложении: версия и сборка совпадают с отправляемым билдом, ссылки на политику и условия открываются.

## Лейблы приватности App Store

Заполняются по `ios/CountryFlagsApp/PrivacyInfo.xcprivacy` — манифест и лейблы
обязаны совпадать. Ни один пункт не используется для трекинга.

| Данные | Связаны с пользователем | Зачем | Когда собираются |
| --- | --- | --- | --- |
| Адрес электронной почты | Да | Работа приложения | При входе через Apple или Google — токен уходит на бэкенд, адрес хранится там |
| Идентификатор пользователя | Да | Работа приложения, аналитика | Всегда: ответы должны лечь в правильный аккаунт |
| Взаимодействие с приложением | Да | Аналитика | Только при включённой продуктовой аналитике |
| Данные о сбоях | Да | Работа приложения | Только при включённой диагностике |
| Данные о производительности | Да | Работа приложения | Только при включённой диагностике |

Оба переключателя выключены по умолчанию, и выключение удаляет то, что не
успело уйти.

## Что может проверить ревьюер без входа

Всё основное. Гость открывает каталог, проходит тренировку, видит прогресс и
карту — аккаунт нужен только для синхронизации между устройствами. Отдельная
демо-учётка не требуется; в заметке для ревью достаточно написать, что вход
необязателен.

## Mock-бэкенда в релизной сборке нет

Раньше был: Xcode линкует продукты Swift-пакета во всех конфигурациях и
копирует их ресурсы рядом с приложением, так что в сборку для App Store
попадали фикстуры мока и строка `mock.invalid` — 1,3 МБ, до которых не
дотягивался ни один путь исполнения. Линковка — свойство цели, а не
конфигурации, поэтому целей приложения теперь две: `CountryFlagsApp` уходит в
магазин и модуль `CountryFlagsMockBackend` не подключает, а
`CountryFlagsAppMock` собирает те же исходники вместе с моком — на нём работают
UI-тесты и схема `CountryFlags-Mock`.

`check-release-app.sh` проверяет собранное приложение тремя способами: нет
ресурсного бандла мока, нет ни одного файла фикстур (по именам из исходного
дерева — переименование бандла проверку не обходит) и нет строк модуля в
бинарниках.

## Порядок выпуска

1. Поднять `MARKETING_VERSION` в `ios/Config/App.xcconfig`, если меняется
   версия. Файл один на обе цели приложения.
2. Запустить `iOS release to TestFlight` из вкладки Actions, указав следующий номер сборки.
3. Дождаться артефактов: `.ipa` и `dSYMs` (символы хранятся 90 дней — без них отчёт о сбое нечитаем).
4. Пройти ручной чек-лист выше на реальном устройстве.
5. Заполнить лейблы приватности по таблице.
