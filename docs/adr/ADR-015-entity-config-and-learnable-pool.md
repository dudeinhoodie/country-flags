# ADR-015 — Учебный пул не зависит от списка «Все страны»; конфигурация сущности живёт в `config`

## Статус

Принято (2026-08-26).

## Контекст

До этого решения `includeInCountryCatalog` определял «текущий каталог»
целиком: членство в колоде «Все страны» (`all-current`), карточный пул
(учебная карточка строилась только для членов `deck.all`), публикацию
фактов и обход таксономии при резолве региональных колод.

Первая же редакционная правка через админ-консоль показала, что это не та
семантика, которую имеет в виду владелец продукта. Скрытие Антарктиды из
списка всех стран (`includeInCountryCatalog: false`) молча лишило её
карточки и фактов и выкинуло из всех колод разом; колода, собранная из
регионов, опубликовалась пустым документом, потому что члены без карточек
молча отбрасываются проекцией.

Намерение владельца (2026-08-26): тогл управляет только присутствием в
списке «Все страны»; сущность остаётся полноценной — карточка, факты,
членство в других колодах — и доступной для добавления в любую колоду,
даже если сейчас не состоит ни в одной; такие конфигурационные признаки
живут в отдельном объекте `config` сущности, а не голыми булями на верхнем
уровне.

## Решение

1. **Обучаемый пул** — активные сущности типов `country`, `territory`,
   `area`. Пул определяет: учебные карточки (одна на сущность пула),
   записи фактов, отчёты о недостающих переводах и ассетах, и множество,
   которым фильтруется обход таксономии. Тогл на пул не влияет.
2. **`config.includeInCountryCatalog`** читает ровно одно место — резолв
   `all-current`, то есть состав колоды «Все страны». В editorial-схеме v2
   тогл переезжает в объект `config` сущности; будущие презентационные
   тогл-поля добавляются туда же. Собранный (published) каталог сохраняет
   плоское поле `includeInCountryCatalog` — это опубликованная форма, а не
   структура источника, и клиенты с бэкендом её уже читают.
3. **Резолвер черновиков зеркалит пайплайн** (deck-membership ↔ merge):
   `learnableEntityKeys` и `currentEntityKeys` считаются по одним правилам
   с обеих сторон; parity-спека продолжает пиновать равенство.
4. **Член колоды без карточки — именованное предупреждение валидации**
   (`MEMBER_NOT_LEARNABLE`, для неизвестного ключа — `MEMBER_UNKNOWN`),
   а не молчаливо пустеющая колода. Это предупреждение, не блокер:
   редактор вправе держать в списке сущность, которая обучаемой станет
   позже.
5. **Миграция**: editorial-схема v2 (`schemaVersion: 2`,
   `editorial-catalog.v2.schema.json`), каталог перезаписан канонической
   сериализацией, пин checksum'а обновлён. Черновики со схемой v1 в БД
   поднимаются до v2 при чтении (`normalizeEditorialDocument`); следующая
   запись сохраняет уже новую форму. Admin API остаётся плоским:
   `includeInCountryCatalog` в запросах и ответах консоли не меняется,
   маппинг в `config` — забота бэкенда.

## Последствия

- Скрытая из «Всех стран» сущность остаётся полноценной: карточка и факты
  публикуются, таксономические и explicit-колоды её сохраняют.
- Контрактный тест пайплайна пинует размер обучаемого пула (250), а не
  количество отмеченных флагом сущностей: редакционное скрытие больше не
  ломает сборку.
- Колода из необучаемых сущностей (например, регионов) по-прежнему
  публикуется пустой — теперь об этом говорит валидация до proposal.
  Колода регионов станет возможной, только когда у регионов появятся
  ассеты и тип войдёт в пул — отдельное продуктовое решение.
- Пайплайн собирает карточки для всего пула, поэтому активная обучаемая
  сущность без флага-ассета — ошибка сборки независимо от членства в
  колодах (раньше — только для членов `deck.all`).
- Существующий proposal PR, открытый до миграции, несёт документ v1 и
  устаревшую базу; его дешевле закрыть и переоткрыть из консоли, чем
  мигрировать на ветке.
