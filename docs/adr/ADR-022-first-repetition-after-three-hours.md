# ADR-022: первый повтор через три часа, а не через час

- Status: Accepted
- Date: 2026-09-11
- Extends: [ADR-013](./ADR-013-first-repetition-after-an-hour.md)

## Context

ADR-013 поднял первую ступень с минуты до часа: лестница
`fsrs-6-default-21-v2` — `learning_steps: ["1h", "3h", "1d"]`,
`relearning_steps: ["1h"]`. С тех пор продукт отказался от четырёх кнопок
оценки в пользу свайпа: влево — «снова», вправо — «хорошо»; «трудно» и
«легко» остались только как accessibility actions. При такой раскладке
часовая ступень была единственным способом вернуть карточку в тот же день:
«хорошо» на новой карточке и так ждало три часа.

Владелец сформулировал ожидание прямо: колода к повторению должна
приходить раз в три часа. На уровне планировщика это выражается одним
правилом — ни один ответ не возвращает карточку раньше чем через три часа.

## Decision

Новая неизменяемая definition `fsrs-6-2026-09-11` с параметрами
`fsrs-6-default-21-v3`:

- `learning_steps: ["3h", "3h", "1d"]`;
- `relearning_steps: ["3h"]`;
- веса, `request_retention`, `maximum_interval`, `enable_fuzz` и
  `enable_short_term` — без изменений.

Лестница читается так: «снова» — через три часа, «хорошо» на новой карточке
— через три часа, следующая ступень — сутки, «легко» выводит карточку в
обычные повторы сразу. Две одинаковые ступени намеренно: первая держит пол
для «снова», вторая — прежний ритм для «хорошо»; убрать вторую значило бы
отправить полностью пройденное занятие сразу на завтра.

`LocalSchedulerProjection` — офлайновая оценка срока на клиенте, для гостя
единственная — приведена к тому же полу: «снова» — три часа, «трудно» —
шесть, «хорошо» — три часа для новой карточки и сутки для отвеченной,
«легко» — сутки и трое. Порядок ступеней сохранён ради accessibility
actions.

## Consequences

- История не переписывается: каждый review хранит версию, под которой был
  принят; карточки, расписанные по v2, доигрывают по v2 и переходят на
  новую лестницу со следующим ответом (механика ADR-004).
- Миграция `20260911150000_scheduler_first_step_three_hours` переводит
  `fsrs-6-2026-08-21` в `RETIRED` и вставляет `fsrs-6-2026-09-11` как
  `ACTIVE`.
- Золотые фикстуры v1 и v2 нетронуты; рядом появилась
  `contracts/fixtures/scheduler/fsrs-6-default-v3.json`, сгенерированная
  адаптером на той же последовательности из четырёх ответов. Тест-пол в
  адаптере держит три часа; попытка вернуть часовую ступень упадёт на нём.
- Занятие, пройденное целиком, возвращается через три часа, а не через час
  для «снова» — это и было целью.

## Alternatives

- **`["3h", "1d"]`, `["3h"]`.** Проще лестница, но «хорошо» на новой карточке
  уходило бы сразу на сутки, и полностью пройденное занятие возвращалось бы
  завтра — не «раз в три часа».
- **Править параметры v2 на месте.** Запрещено ADR-004.
- **Поднять пол только на клиенте.** Расходилось бы с тем, что бэкенд
  показывает другим устройствам; бэкенд — единственный судья (ADR-016).
