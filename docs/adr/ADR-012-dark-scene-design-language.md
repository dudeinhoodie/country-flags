# ADR-012 — Тёмная сцена как визуальный язык и iOS 26 как минимальная версия

## Статус

Принято (2026-08-15).

## Контекст

`docs/16-ios-design-language.md` предписывал нативную хрому: системные
компоненты, светлую/тёмную тему вслед за системой, системные индикаторы,
минимум собственного рисования. Реализованный в августе 2026 редизайн
(PR #123 и далее) осознанно ушёл от этого к собственному языку: тёмная
«сцена», подсвеченная цветами текущего флага, стеклянные панели, колода
карточек со свайпами, hero-числа на экранах. Продукт-владелец принял
направление по живому прототипу и серии итераций в симуляторе.

Одновременно держать документ, требующий нативной хромы, и кодовую базу,
рисующую собственную сцену, — значит врать одному из них. Этот ADR
фиксирует новый канон и снимает противоречие.

Отдельно: язык построен на стекле. До сих пор он собирался на
`ultraThinMaterial`/`regularMaterial` при таргете iOS 17, потому что
нативная система материалов «жидкого стекла» появилась только в iOS 26.
Приложение ещё не выпускалось, пользователей со старыми версиями не
существует, парк симуляторов и CI уже на iOS 26.

## Решение

1. **Минимальная версия — iOS 26.0** (`IPHONEOS_DEPLOYMENT_TARGET`,
   `Package.swift`). Первый релиз, чья система материалов рисует то
   стекло, на котором стоит дизайн. Поднятие пола до выпуска не стоит
   никому обновления; иммиграция на нативные стеклянные API — отдельная
   работа, разрешённая этим решением, но им не требуемая.

2. **Сцена принадлежит приложению.** Тёмная основа с радиальными
   светами: в сессии — цветами текущего флага (`FlagPaletteReader`),
   вне её — двумя фирменными цветами. Приложение тёмное всегда
   (`preferredColorScheme(.dark)`): сцена и есть тема, системная светлая
   тема с ней несовместима.

3. **Стекло — материал интерфейса.** Панели, капсулы, плитки — глухие
   стеклянные поверхности с волосяной рамкой (`GlassCard`,
   `SectionLabel`, `PrimaryActionStyle`, `GlassActionStyle`). Белая
   капсула — максимум контраста, тратится один раз на экран.

4. **Свои фигуры разрешены там, где системные не умеют смысл**:
   полоса прогресса колоды (системный индикатор тащит собственный
   трек-материал), hero-числа (`Typography.heroNumber`), колода со
   свайпами и рассыпанной стопкой. Правила «цвет — не единственный
   носитель», «флаг не кадрируется и не растягивается», токены вместо
   голых чисел — сохраняются из `docs/16` без изменений.

5. **Исключение для товарных знаков.** Логотипы провайдеров (четырёхцветная
   «G») несут собственную палитру, как флаг несёт свою: запрет
   hex-литералов на них не распространяется.

6. **Настройки — единственный экран без героя**: системная форма на
   стеклянных подложках. Узнаваемость платформенных контролов там ценнее
   собственного рисования.

## Последствия

- `docs/16` читается через призму этого ADR: разделы о нативной хроме и
  системной теме — исторический контекст, не действующее требование.
- Появляется возможность (и отдельная задача) заменить
  `ultraThinMaterial`-приближения на нативные стеклянные API iOS 26.
  Выполнено: хром — панели (`GlassCard`), капсулы действий, плавающие
  кнопки и чипы — переведён на `glassEffect`/`buttonStyle(.glass)`;
  рукодельные hairline-обводки сняты, у нативного стекла своя кромка.
  Материалы намеренно остались там, где поверхность — контент, а не
  хром: скелетоны загрузки, фон строк настроек, подложка аватара,
  рубашка карточки.
- Любая новая поверхность обязана строиться из компонентов сцены
  (`Design/`), а не из системных списков со своим фоном.
- Открытыми остаются акцентный цвет и иконка приложения — решения
  продукт-владельца, ADR их не предвосхищает.
