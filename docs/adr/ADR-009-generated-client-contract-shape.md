# ADR-009: Форма контракта для генерируемых клиентов

- Status: Proposed
- Date: 2026-08-07

## Context

iOS MVP обязан потреблять канонический `contracts/openapi.yaml` через официальный
Swift OpenAPI Generator и не создавать несовместимые handwritten DTO. Проверка
bundled-контракта генератором (IOS-000) выявила два свойства, из-за которых
сгенерированный клиент не соответствовал ТЗ.

1. Генератор выпускает закрытый Swift enum для каждого `enum` в схеме.
   Неизвестное значение приводит к ошибке декодирования всего payload, а не
   одного поля. `docs/02-ios-spec.md` §6.2 требует обрабатывать неизвестное
   enum через `unknown`, а не терять данные.
2. Генератор не поддерживает `oneOf: [$ref, {type: "null"}]` и молча
   выбрасывает такое свойство из сгенерированного типа. Из клиента пропадали
   `StudySession.summary`, `ReviewResult.canonicalRating`,
   `ReviewResult.cardState`, `UserChange.payload`, `Deck.currentMasteryTier` и
   `Achievement.tier`, то есть канонический card state и результат сессии —
   данные, без которых невозможны sync (§8) и Session Result (§9.7).

Контракт при этом остаётся единственным источником истины для всех клиентов, а
не только для Swift, поэтому решение не должно опираться на особенности одного
генератора сильнее необходимого.

## Decision

- Разделить string enum по владельцу значения.
  - Протокольные и state-значения (`AnswerMode`, `Rating`, `SelectionOrigin`,
    статусы сессии, `CardState.state`, статус результата review, `MasteryTier`,
    `AuthProvider`, platform, consent, все request-поля) остаются закрытым
    `enum`. Добавление значения — breaking change с major-версией API.
  - Значения, которыми владеет content pipeline (`Asset.type`, `Fact.type`,
    `GeoEntity.kind`, `GeoEntity.recognitionStatus`, `Deck.kind`,
    `ContentChange.resourceType`, `StudySessionCard.selectionReason`,
    `UserSettings.extraFactTypes`), объявляются как `type: string` с
    аннотацией `x-extensible-enum`, содержащей известные сегодня значения.
- `x-extensible-enum` не сужает wire-формат и не влияет на серверную валидацию;
  это документация для клиентов и генераторов.
- Клиент обязан отображать значение вне списка в собственный
  `unknown(String)`, сохранять остальной payload и деградировать только
  затронутый элемент интерфейса.
- Nullable-структуры описываются обычным `$ref` и остаются необязательным
  свойством. Backend опускает такое поле вместо `null`.
- Отсутствие значения и `null` для клиента эквивалентны: `decodeIfPresent`
  обрабатывает оба варианта, поэтому правило не ломает уже написанный клиент.
- Правило проверяется воспроизводимой сборкой `contracts/swift-client-check`,
  которая генерирует клиент из bundled-контракта и декодирует committed
  fixtures.

## Consequences

- Content release может добавить значение таксономии без версии API и без
  обновления клиентов.
- Расширяемые поля теряют типизацию на уровне сгенерированного кода; типобезопасность
  переносится в клиентскую обёртку `ExtensibleEnum`.
- Ответы больше не содержат `null` для структурных полей; клиент отличает
  «нет значения» по отсутствию ключа.
- Появляется обязательство поддерживать `x-extensible-enum` в актуальном
  состоянии при изменении content pipeline.
- Регрессия формы контракта ловится в CI только при запуске Swift-проверки,
  которая требует Swift toolchain и сети.

## Alternatives

- Оставить закрытые enum и обрабатывать ошибку декодирования на клиенте:
  теряется весь ответ, а не одно поле.
- Сделать все enum строками: исчезает контроль протокольных значений и
  безопасность state machine.
- Инлайнить nullable-структуры с `type: ["object","null"]`: дублирует схемы и
  ломает переиспользование `$ref`.
- Держать отдельный «клиентский» вариант контракта: два источника истины,
  прямо запрещённые правилами репозитория.

## Revisit triggers

- Swift OpenAPI Generator добавляет поддержку open enum или nullable `$ref`.
- Появляется второй генератор (Android, web) с иными ограничениями.
- Принято решение по `additionalProperties: false` в response-схемах.
